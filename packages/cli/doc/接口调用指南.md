# @mp-assistant/cli 接口调用指南

本文档说明如何通过 bash/curl 调用 @mp-assistant/cli 启动的服务所提供的「获取 Worker 列表」和「添加任务」接口。

**约定**：`{BASE_URL}` 表示 CLI 服务地址，例如 `http://localhost:3000`。服务启动后会输出实际地址，API 路径前缀为 `/api`。

---

## 一、获取 Worker 列表

### HTTP 请求

| 项目 | 值 |
|------|-----|
| Method | `GET` |
| URL | `{BASE_URL}/api/worker-list` |
| Query | 无 |
| Headers | 无特殊要求 |
| Body | 无 |

### bash 示例

```bash
curl -X GET "{BASE_URL}/api/worker-list"
```

### 响应格式

**成功**（HTTP 200）：

```json
{
  "code": 200,
  "message": "string",
  "data": [
    {
      "key": "worker唯一标识",
      "name": "Worker名称",
      "type": "wx",
      "taskList": [
        {
          "workerKey": "worker的key",
          "key": "任务key",
          "type": "wxnInspectVersion",
          "status": "completed",
          "runningReportList": [{ "title": "切换小程序成功", "timestamp": 1234567890 }],
          "options": { "app_name": "xxx", "username": "gh_xxx" },
          "result": {
            "data": {
              "online_info": { "version": "1.0.0", "describe": "线上", "audit_status": 2 },
              "experience_info": { "version": "1.0.1", "describe": "审核版", "audit_status": 1 },
              "develop_info": [{ "version": "1.0.2", "describe": "开发版", "nick_name": "开发者" }]
            }
          },
          "createTime": 1234567890,
          "startTime": 1234567890,
          "endTime": 1234567890
        }
      ],
      "status": "running",
      "loadings": [],
      "isLogin": true,
      "loginQRCodeFilePath": "文件路径",
      "wxaList": [
        {
          "appid": "小程序appid",
          "app_name": "小程序名称",
          "username": "小程序原始id",
          "app_headimg": "头像URL",
          "email": "",
          "type": ""
        }
      ]
    }
  ]
}
```

> taskList 中 `result` 结构依任务类型不同，详见下方「taskList 与 result 结构」。

**失败**：`code` 为 400/401/403/404/500，`data` 为 `null`，`message` 为错误说明。

**data 字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `key` | string | Worker 唯一标识，添加任务时作为 query 参数 |
| `name` | string | Worker 名称 |
| `type` | string | Worker 类型，如 `"wx"` |
| `taskList` | array | 该 Worker 下的任务列表，见下方「taskList 与 result 结构」 |
| `status` | string | `paused` / `deleted` / `running` |
| `loadings` | string[] | 当前加载中的操作 |
| `isLogin` | boolean | 是否已登录（微信 Worker） |
| `loginQRCodeFilePath` | string | 登录二维码文件路径（微信 Worker） |
| `wxaList` | array | 已绑定的小程序列表（微信 Worker） |

**wxaList 项**：`appid`、`app_name`、`username` 用于构建添加任务时的 `options`。

### taskList 与 result 结构

**taskList 公共字段**（BaseTaskInfo）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `workerKey` | string | 所属 Worker 的 key |
| `key` | string | 任务唯一标识 |
| `type` | string | 任务类型：`wxnInspectVersion` / `wxnAudit` / `wxnPublish` |
| `status` | string | `notStarted` / `running` / `completed` / `failed` |
| `runningReportList` | array | 执行过程报告，见下方 |
| `options` | object | 任务入参，与添加任务时的 options 一致 |
| `result` | object | 执行结果，**依任务类型不同**，见下方 |
| `createTime` | number | 创建时间戳 |
| `startTime` | number | 开始时间戳 |
| `endTime` | number | 结束时间戳 |

**runningReportList 项**（TaskRunningReport）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `title` | string | 报告标题 |
| `timestamp` | number | 时间戳 |
| `description` | string | 可选，描述 |
| `images` | string[] | 可选，截图文件路径数组 |

**result 按任务类型**：

| 任务类型 | result 结构 | 说明 |
|----------|-------------|------|
| `wxnInspectVersion` | `{ data?: VersionListData, msg?: string }` | 成功时有 `data`，失败时有 `msg` |
| `wxnAudit` | `{ msg?: string }` | 仅 `msg`，无 `data` |
| `wxnPublish` | `{ msg?: string }` | 仅 `msg`，无 `data`；任务本身另有 `publishQRCodeFilePath`、`countdown`、`refreshLoading` |

#### 1. 版本检查任务 (wxnInspectVersion) 的 result.data

`result.data` 为 **VersionListData**，结构如下：

```json
{
  "online_info": { /* VersionListItem，线上版本，单对象 */ },
  "experience_info": { /* VersionListItem，体验版/审核版，单对象 */ },
  "develop_info": [ /* VersionListItem 数组，开发版列表 */ ]
}
```

**VersionListItem** 字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `version` | string | 版本号 |
| `describe` | string | 版本备注 |
| `nick_name` | string | 发布者昵称 |
| `audit_status` | number | 审核状态：1=审核中，2=通过，3=拒绝 |
| `audit_id` | number | 审核 id |
| `fail_reason` | string | 审核失败原因 |
| `status` | number | 状态 |
| `time` | number | 时间戳 |
| `avatar` | string | 头像 |
| `open_id` | string | openid |
| `is_speedup` | number | 是否加急 |
| `warning_api_list` | array | 告警 API 列表 |
| `is_exper` | boolean | 是否体验版（仅 develop_info 项可能有） |

#### 2. 审核任务 (wxnAudit) 的 result

仅包含 `msg`，无 `data`。成功示例：`"提审成功"`、`"当前版本已通过审核，请发布"`；失败时为错误说明。

#### 3. 发布任务 (wxnPublish) 的 result 与任务扩展字段

`result` 仅包含 `msg`，无 `data`。成功示例：`"发布成功"`；失败时为错误说明。

发布任务在 `taskList` 中还有额外字段（执行中或完成后可能有）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `publishQRCodeFilePath` | string | 发布二维码截图文件路径 |
| `countdown` | number | 二维码剩余有效秒数 |
| `refreshLoading` | boolean | 是否正在刷新二维码 |

## 二、添加任务

### HTTP 请求

| 项目 | 值 |
|------|-----|
| Method | `POST` |
| URL | `{BASE_URL}/api/worker-addTask` |
| Query | `key`（必填）：Worker 的 key，来自「获取 Worker 列表」返回的 `data[].key` |
| Headers | `Content-Type: application/json` |
| Body | JSON 对象，见下方 |

### 请求体 (Body)

```json
{
  "type": "任务类型字符串",
  "options": { }
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `type` | string | 是 | 任务类型，见下表 |
| `options` | object | 是 | 任务选项，依 `type` 不同而不同 |

**type 取值**：

| 值 | 含义 |
|----|------|
| `wxnInspectVersion` | 检查小程序版本 |
| `wxnAudit` | 审核 |
| `wxnPublish` | 发布 |

### options 结构（按 type）

#### 1. 版本检查 (wxnInspectVersion)

```json
{
  "type": "wxnInspectVersion",
  "options": {
    "app_name": "小程序名称",
    "username": "小程序原始id"
  }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `app_name` | string | 来自 wxaList 的 `app_name` |
| `username` | string | 来自 wxaList 的 `username` |

#### 2. 审核 (wxnAudit)

```json
{
  "type": "wxnAudit",
  "options": {
    "app_name": "小程序名称",
    "username": "小程序原始id",
    "positioner": [
      {
        "type": "describe",
        "criteria": "Equal",
        "value": "版本备注值"
      }
    ],
    "populateData": {
      "versionDescription": "版本描述",
      "imagePreview": "path1.jpg,path2.png",
      "videoPreview": "path.mp4"
    }
  }
}
```

**positioner**（版本定位条件，可选）：

| 字段 | 类型 | 取值 |
|------|------|------|
| `type` | string | `describe`（备注）/ `nick_name`（发布者）/ `version`（版本号） |
| `criteria` | string | `Equal`（相等）/ `Inclusion`（包含） |
| `value` | string | 匹配值 |

**populateData**（可选）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `versionDescription` | string | 版本描述 |
| `imagePreview` | string | 图片路径，多个用英文逗号 `,` 分隔 |
| `videoPreview` | string | 视频路径，多个用英文逗号 `,` 分隔 |

#### 3. 发布 (wxnPublish)

```json
{
  "type": "wxnPublish",
  "options": {
    "app_name": "小程序名称",
    "username": "小程序原始id",
    "positioner": [
      {
        "type": "nick_name",
        "criteria": "Equal",
        "value": "发布者"
      }
    ]
  }
}
```

`positioner` 格式同上。

### bash 示例

```bash
# 版本检查
curl -X POST "{BASE_URL}/api/worker-addTask?key=WORKER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"type":"wxnInspectVersion","options":{"app_name":"我的小程序","username":"gh_xxx"}}'

# 审核
curl -X POST "{BASE_URL}/api/worker-addTask?key=WORKER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"type":"wxnAudit","options":{"app_name":"我的小程序","username":"gh_xxx","positioner":[{"type":"describe","criteria":"Equal","value":"v1.0"}],"populateData":{"versionDescription":"更新说明","imagePreview":"a.jpg,b.png","videoPreview":""}}}'

# 发布
curl -X POST "{BASE_URL}/api/worker-addTask?key=WORKER_KEY" \
  -H "Content-Type: application/json" \
  -d '{"type":"wxnPublish","options":{"app_name":"我的小程序","username":"gh_xxx","positioner":[{"type":"version","criteria":"Equal","value":"1.0.0"}]}}'
```

### 响应格式

**成功**（HTTP 200）：

```json
{
  "code": 200,
  "message": "string",
  "data": { /* 更新后的 Worker 对象，结构同「获取 Worker 列表」的 data 项 */ }
}
```

**失败**：`code` 非 200，`data` 为 `null`，`message` 为错误说明。

## 三、调用流程

1. 启动 @mp-assistant/cli 服务，获取服务地址（如 `http://localhost:3000`）。
2. 调用 `GET {BASE_URL}/api/worker-list` 获取 Worker 列表。
3. 从返回的 `data` 中取目标 Worker 的 `key`。
4. 从该 Worker 的 `wxaList` 中取目标小程序的 `app_name`、`username`。
5. 按任务类型构造 `options`，调用 `POST {BASE_URL}/api/worker-addTask?key={key}`，Body 为 `{ type, options }`。
